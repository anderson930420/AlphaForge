# Phase 27 — Local Research Dashboard

## Goal

Phase 27 adds a local-first dashboard layer for AlphaForge ML research artifacts.
It does not change the ML pipeline, signal construction semantics, or backtest
execution behavior. The dashboard reads artifacts that were already generated by
existing CLI/script workflows and presents them in a browser-friendly interface.

## Scope

The dashboard expects an artifact directory containing files from the end-to-end
ML artifact smoke workflow:

```text
return_labels.csv
supervised_panel.csv
dataset.csv
predictions.csv
metrics_summary.json
ml_signal.csv
report.html
smoke_summary.json
```

The implementation has two layers:

1. `alphaforge.dashboard_artifacts`
   - Pure Python artifact loading and summarization layer.
   - Reads CSV/JSON/HTML artifact presence.
   - Reports present/missing files.
   - Produces table shape, columns, and preview rows.
   - Has deterministic unit tests and does not import Streamlit.

2. `alphaforge.dashboard_app`
   - Optional Streamlit UI layer.
   - Displays overview metrics, pipeline status, JSON summaries, table previews,
     and embedded `report.html`.
   - Requires the optional `dashboard` extra.

## Usage

Generate the smoke artifacts first:

```bash
PYTHONPATH=src python3 scripts/run_ml_artifact_smoke.py \
  --features tests/fixtures/return_labels/features.csv \
  --returns tests/fixtures/return_labels/monthly_returns.csv \
  --output-dir artifacts/phase25/ml_artifact_smoke
```

Install dashboard dependencies:

```bash
python -m pip install -e ".[dashboard]"
```

Run the dashboard:

```bash
PYTHONPATH=src streamlit run src/alphaforge/dashboard_app.py
```

Default artifact directory:

```text
artifacts/phase25/ml_artifact_smoke
```

You can change the artifact directory from the Streamlit sidebar.

## Local-first data boundary

The dashboard is intentionally local-first. It reads local artifacts and does not
upload private data to a hosted service. For portfolio or interview demos, use
checked-in fixtures or sanitized generated artifacts.

## Validation

Recommended checks:

```bash
git diff --check
PYTHONPATH=src python3 -m pytest tests/test_dashboard_artifacts.py -q
PYTHONPATH=src python3 -m pytest -q
```

## Boundary

This phase does not:

- train new models
- add deep learning
- modify custom_signal semantics
- modify backtest execution
- download private OAP/CRSP/WRDS data
- require Streamlit for the core package or test suite
